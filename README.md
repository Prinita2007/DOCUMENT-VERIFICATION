# Intelligent Academic Document Verification and Fraud Detection

## Dataset research and access

See [datasets/dataset_sources.csv](./datasets/dataset_sources.csv).

- **DocTamper** directly addresses document tampered-text localization. Its official project states non-commercial/restricted academic use and requires an access request. Its labels are not academic-certificate fraud ground truth.
- **MIDV-2020** is a mock identity-document benchmark, not an academic certificate dataset. The official page requires an access request and acceptance of its license; reported archive size is 124 GB.
- **RVL-CDIP** is a document-type classification corpus, not a tampering dataset. Its old linked page redirected during inspection; current official availability and license still require confirmation.

No datasets have been downloaded. Do not copy data until you/your supervisor verify and accept the current official terms. Never commit raw datasets or real student records.

## Windows setup

Open PowerShell in this project folder.

### 1. Install Python dependencies

```powershell
.\backend\venv\Scripts\python.exe -m pip install -r .\requirements.txt
```

For a fresh workspace, create the venv first with `py -3.14 -m venv .\backend\venv` (or use an installed supported Python version), then run the pip command above.

### 2. Configure PostgreSQL 18

Do not reset the PostgreSQL password or weaken `pg_hba.conf` authentication. In pgAdmin, use an administrator account to create the `document_verification` database and a dedicated login role for the application; grant that role only database `CONNECT` and schema `USAGE`/`CREATE` rights needed for migrations. Do not use the `postgres` superuser as the app account.

The local PostgreSQL service was found running, but authentication did not succeed because a usable application password is not configured in this workspace. The safe manual action is to enter a valid password in your private local `.env`, or create a separate least-privilege app role via pgAdmin. No password should be pasted into chat or committed.

```powershell
if (-not (Test-Path .\.env)) { Copy-Item .\.env.example .\.env }
```

Edit `.env` privately:

```text
DATABASE_URL=postgresql+psycopg://document_verification_app:URL_ENCODED_PASSWORD@localhost:5432/document_verification
JWT_SECRET=PASTE_A_RANDOM_SECRET_OF_AT_LEAST_32_CHARACTERS
```

URL-encode special characters in the database password. Generate the JWT secret locally (for example with Python `secrets.token_urlsafe(48)`). `.env` is ignored by Git.

Apply migrations (after the database role can connect):

```powershell
.\backend\venv\Scripts\python.exe .\database\init_db.py
```

This applies Alembic migrations; it does not drop existing tables. Back up databases before schema changes. `database\create_database.py` is optional and requires a role with `CREATEDB`; prefer creating the database in pgAdmin rather than elevating the application role.

### 3. Configure Tesseract OCR

The Python `pytesseract` integration is not the OCR engine itself. The actual Tesseract executable was not found on PATH during inspection. Follow the [Tesseract installation documentation](https://tesseract-ocr.github.io/tessdoc/Installation.html), including its Windows guidance, and obtain any installer/admin permission required yourself. Then add to `.env` the actual local executable path, for example:

```text
TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe
```

Verify in PowerShell with `tesseract --version` (or the configured full path plus `--version`) and check `GET /health`; OCR remains unavailable until the engine and language data are correctly installed.

### 4. Create an administrator

After migrations and PostgreSQL connectivity work:

```powershell
.\backend\venv\Scripts\python.exe .\backend\create_admin.py
```

Enter a unique username and a password of at least 12 characters when prompted. The password is not included in the command and is hashed with Argon2.

### 5. Start services

Backend, from the project root:

```powershell
.\backend\venv\Scripts\python.exe -m uvicorn main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```

Frontend, in a second PowerShell terminal:

```powershell
Set-Location .\frontend
npm install
npm run dev
```

Open <http://127.0.0.1:5173>. API docs are at <http://127.0.0.1:8000/docs>, and `GET /health` reports database and OCR engine status. The backend is configured to use PostgreSQL by default; it does not silently switch to SQLite. SQLite is used by isolated tests only.

## AI/ML experiment workflow

Training requires a licensed dataset and a reviewed manifest. Required columns are `image_path,label,group_id`; labels are exactly `authentic` and `tampered`. All source images and their edited/scanned derivatives must share the same group ID.

```powershell
.\backend\venv\Scripts\python.exe -m ml.train_classical --manifest .\datasets\raw\approved_manifest.csv --image-root .\datasets\raw
.\backend\venv\Scripts\python.exe -m ml.train_cnn --manifest .\datasets\raw\approved_manifest.csv --image-root .\datasets\raw
```

These are input-path examples; do not create labels from document-type categories. The pipeline cleans missing/unreadable records, removes exact duplicates, extracts image features, applies imputation/scaling/feature selection, performs group-disjoint train/validation/test splits, tunes supervised estimators with grouped cross-validation, fits Isolation Forest on authentic training data, and evaluates only on held-out groups. It generates:

- Processed tables/split assignment: `datasets/processed/`
- EDA distributions, correlation, missing-value and outlier plots: `results/eda/`
- Metrics, CV tables, confusion matrices, ROC curves, SHAP plot and model comparison: `results/evaluation/`
- Classical model and CNN artifacts: `models/`

No model weights or metrics are shipped. Do not cite synthetic unit-test outputs as experiment results.
